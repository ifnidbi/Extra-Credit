# Final report checklist

Prepare a 10–12 page report in Times 11. Use your actual screenshots, test outcomes, and contributions. The [course coverage table](course-coverage.md) maps the app to the handout.

| Section | What to include |
| --- | --- |
| Abstract | Summarize the Ontario Tech student marketplace, the database design, and one measured or demonstrated result. |
| Introduction and goals | Explain the problem with finding and selling secondhand goods at Ontario Tech, the two Oshawa locations, and the project goals. |
| Related work | Compare the concept to the related projects in the proposal. Check your references before submitting. |
| Design and schematics | Include the [ER diagram](database.md#entity-relationship-diagram), the [architecture diagram](architecture.md#architecture-diagram), six tables, keys, major constraints, and schema changes since Phase II. Explain why prices are grouped by currency. |
| Implementation and course connection | Show Ontario Tech email confirmation, sessions and roles, listing CRUD, photo uploads, filters, buyer and seller inquiries, Fetch, Chart.js, both exports, and the Open-Meteo integration. Explain the transaction used to accept an inquiry and reserve the listing. |
| Results and analysis | Include one clearly labeled result screenshot for each of the ten views. Also show sample row counts, key CRUD outcomes, search, chart, exports, and the weather INSERT and SELECT. Add actual correctness checks and performance measurements. |
| Conclusions, problems, and future work | State what worked, a bug you reproduced and fixed, test limits, and what you would add next. Good future-work examples are university enrollment integration and deployment. Explain View 4's MySQL equivalent and document any TA response you have. |
| References and contributions | Cite sources and libraries, include the contribution matrix, and describe the foundation PR and AI-assisted implementation accurately. Record each team member's actual work and follow your course's AI disclosure requirements. |

Use the [query and demo evidence](query-evidence.md) to locate captures and reproduce them. Include a screenshot for every query discussed in the report. For the presentation, prepare 5–7 minutes of slides and a live walkthrough. Rehearse with a timer and keep the [backup demo video](evidence/backup-demo.mp4) available. Allow two minutes for questions. The team evaluation uses the course's submission process.
